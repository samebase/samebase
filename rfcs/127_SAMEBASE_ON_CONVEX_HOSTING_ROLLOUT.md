## Summary

1. samebase.com becomes a custom domain of the production Convex deployment `clear-butterfly-858`.
   `convex-hosting deploy` uploads `dist/client` and `routeAll` serves it after the existing HTTP
   routes. The `samebase` Worker, Workers Builds, and wrangler go away.
2. The app becomes single-origin. The `CONVEX_SITE_URL` override moves from api.samebase.com to
   samebase.com, so the Convex Auth issuer, the OAuth callbacks, the MCP metadata, and the site all
   live at samebase.com. api.samebase.com stays attached to the same deployment only until the
   published listings point at `https://samebase.com/mcp`. Then it is removed.
3. Deploys and PR previews move to GitHub Actions with the convex-hosting `deploy`, `preview`, and
   `cleanup` actions, in the shape the Mail and Scout apps already use.
4. The work is two repo PRs, one manual cutover, and one listings round. Four package gaps go back
   to convex-hosting.

## Facts

Checked on 2026-10-20 against `origin/main` and the live services.

- The Worker is assets only. `apps/samebase/wrangler.jsonc` has no `main`, no bindings,
  `html_handling: "none"` and `not_found_handling: "single-page-application"`. There is no server
  code at request time: no `createServerFn`, no server routes, no middleware, no Cloudflare API.
  `public/_redirects` (106 lines, generated) and `public/_headers` (33 lines) carry the prerender
  rewrites, the aliases, the CSP, and the `no-store` rules.
- Auth is Convex Auth 0.0.94 with tokens in localStorage
  (`apps/samebase/src/components/AppRootClient.tsx`). Nothing renders auth state on a server.
- `https://api.samebase.com/.well-known/openid-configuration` answers
  `"issuer":"https://api.samebase.com"`. So production overrides `CONVEX_SITE_URL` to
  api.samebase.com today. `SITE_URL` is `https://samebase.com`.
- DNS: `_convex_domains.api.samebase.com` TXT is `clear-butterfly-858`. api.samebase.com and
  samebase.com resolve to the same proxied Cloudflare addresses (104.26.8.5, 104.26.9.5,
  172.67.70.236). `convex.domains` resolves to 104.18.12.229 and 104.18.13.229. So api.samebase.com
  is a proxied (orange cloud) record in the samebase.com zone, the setup Convex calls "advanced",
  and it has worked in production. chessmerge.com (an apex on convex-hosting) resolves to the
  `convex.domains` addresses: an apex works through CNAME flattening.
- www.samebase.com redirects to samebase.com through a zone rule, not through the Worker.
- Shipped values that hard-code api.samebase.com: `packages/plugin/plugins/samebase/.mcp.json`,
  `packages/plugin/server.json`, `apps/samebase/public/llms.txt` (generated by
  `apps/samebase/scripts/generate-action-docs.ts`), `scripts/check-samebase-agent-plugin.ts`, and
  the two plugin READMEs. Every other use derives from `CONVEX_SITE_URL`, `SITE_URL`,
  `PROVIDER_*_REDIRECT_URL`, `GITHUB_APP_OAUTH_CALLBACK_URL`, or the request origin.
- Stored MCP rows hold the resource `https://api.samebase.com/mcp`: `mcpGrants`, `mcpAccessTokens`,
  `mcpAuthorizationRequests`, `mcpAuthorizationCodes`. The checks in
  `apps/samebase/convex/mcp/http.ts` compare it with the request origin.
- `apps/samebase/alchemy.run.ts` (v2123) owns the Worker shell, the Builds link, the deploy key and
  preview key named `workers-builds`, the Convex project, the PostHog proxy Worker, and the domains
  Worker. All are retained on destroy except the domains Worker.
- The build chain lives in `apps/samebase/scripts/build-cloudflare.ts`: it sets
  `VITE_SAMEBASE_ROUTE_ENVIRONMENT`, `SAMEBASE_PRERENDER_ORIGIN=https://samebase.com`,
  `VITE_PUBLIC_POSTHOG_HOST=https://e.samebase.com` and the PostHog token on main, runs
  `convex deploy --cmd`, and seeds `devAuth:seedPasswordAccount` on previews.
- Package contract: core 0.13.1 needs `convex ^1.46.0` (main has 1.46.0) and Node 22 or later. The
  TanStack adapter is not needed for a files-only site.
  `routeAll(http, components.hosting, versionId)` registers `pathPrefix: "/"` for every method.
  Convex matches an exact path first, then the longest prefix, so the existing routes win in any
  order. `_headers` and `_redirects` keep the Cloudflare semantics.
  `--html-handling none --not-found-handling single-page-application` is the Mail shape. The
  per-file cap is 25 MiB; the largest Samebase file is 3.7 MB, and `dist/client` is 395 files, 13
  MB.
- `convex/http.ts` imports `../.convex-hosting/version.js`, a generated state file. Without it,
  `convex dev` and `convex codegen` cannot bundle the router. Only
  `apps/samebase/convex/mcp/http.convex.test.ts` imports a router module, and that is
  `convex/mcp/http.ts`, not the root router.
- PR previews on convex-hosting are Convex preview deployments named after the branch, 14 days on
  Pro. The team reached the 300-deployment quota on 2026-10-18.

## Target

- Browser to `samebase.com`: Cloudflare zone (proxied) to `convex.domains` to the HTTP router of
  `clear-butterfly-858`. The router serves the exact routes first (Convex Auth, provider OAuth
  callbacks, `/.well-known/*`, `/oauth/mcp/*`, `/mcp`, `/webhooks/polar`) and `routeAll` serves the
  files for everything else.
- The Convex client keeps its WebSocket to `clear-butterfly-858.convex.cloud` through
  `VITE_CONVEX_URL`. `e.samebase.com` (PostHog proxy) and `media.samebase.com` do not change.
- PR previews are `https://<branch>.convex.site`. `?prod-ui` keeps working because a `convex.site`
  host is not a production host (`apps/samebase/src/lib/prodUiMode.ts`).

## Cutover Sequence

1. Before the merge: create the two keys and the GitHub secrets, add the PostHog repository
   variable, and add samebase.com as a custom domain in the Convex dashboard next to
   api.samebase.com (the TXT verifies while DNS still points at the Worker; the certificate waits
   for the switch). This step also proves that one deployment accepts two custom domains.
2. Merge PR 1. The deploy workflow uploads the site. Check it at
   `https://clear-butterfly-858.convex.site`. From now on api.samebase.com also serves the site on
   non-API paths; harmless.
3. Disconnect Workers Builds from the `samebase` Worker.
4. Zone: detach the Worker custom domain and add the proxied apex CNAME. The first request mints the
   certificate (up to one minute; verification up to 30 minutes). A short outage is accepted.
5. Convex: set the `CONVEX_SITE_URL` override and the four redirect env vars.
6. Checks: the issuer answers `https://samebase.com`; an open session keeps working; Google and
   GitHub sign-in; a GitHub App install; the three provider OAuth popups; an MCP connect from Claude
   at `https://samebase.com/mcp`; a Polar webhook delivery; the www redirect; the `_headers` rules;
   time to first byte of `/` from Europe compared with today.
7. Merge PR 2. CI publishes the plugin mirror. Run the listings round (section E).
8. After the listings are live: section F.

## Decisions

Each item is the recommendation. Say "no" to change it.

1. samebase.com is proxied through the zone (orange cloud), the shape api.samebase.com runs today.
   It keeps the zone rules, the analytics, and the WAF. The package `docs/domains.md` says the
   record must be DNS only; that is gap 2, not a reason to change the shape.
2. api.samebase.com stays attached until the listings are updated, then goes. Cutting it at the
   merge would break the Claude connector until its review passes.
3. No data migration for the stored MCP resources. The external clients reconnect.
4. Keys through `gh secret set`, not through the Alchemy stack, as in Mail.

## Package Gaps

Report each to [samebase/convex-hosting](https://github.com/samebase/convex-hosting) with the
Samebase case. None of them is worked around in this repo beyond the one-time build in A.

1. The generated version module gates every push. A fresh worktree, the CI local-backend job, and
   codegen all need a full site build before `convex dev` can bundle `http.ts`. Samebase has many
   linked worktrees. Candidate: a way to write a version module with no site (`versionId` null)
   without a build, and `routeAll` answers 404 for it.
2. `docs/domains.md` says the Cloudflare record must be DNS only. api.samebase.com has run proxied
   through the owner's zone, which Convex documents as its advanced setup. Document the proxied
   option with the certificate-renewal watch.
3. `docs/domains.md` says never to override `CONVEX_SITE_URL`. A single-origin app with Convex Auth
   and OAuth callbacks needs exactly that override. Document when it is right and what it changes
   (issuer, redirect base, token refresh).
4. The preview action: Scout and Samebase both set `SITE_URL` on the preview and run a seed function
   after the deploy. Candidate: pass `--preview-run` through to `npx convex deploy`, and an option
   that sets `SITE_URL` to the preview site URL.

## Non-Goals

- Request-time rendering and Convex Auth 2. The site stays a prerendered SPA. Server-side rendering
  is a later project that starts after this move.
- The product's provisioning of user apps on Cloudflare Workers and Workers Builds.
- The PostHog proxy and the domains Worker. They stay on Cloudflare through the stack.
- A custom domain for the Convex API (`.convex.cloud`).
