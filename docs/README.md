# Docs

`docs/` is for durable reference material that supports the repo but does not
itself define current product behavior.

Use `docs/` for:

- workflow runbooks
- compliance and policy artifacts
- operator or release reference material
- reference docs that agents or humans may need to consult, but that are not
  product specs or active proposals

Current key docs:

- `docs/agent-workflows.md` for deeper git/PR/worktree workflow rules
- `docs/compliance/` for compliance artifacts

Do not use `docs/` as a dumping ground for accepted behavior or open-ended
research; put those in `specs/`, `rfcs/`, or `research/` instead.
