# Idea: Give Junior Devs the Senior Stack

## Core positioning

Give your junior devs the same stack your senior engineer actually uses.

## Origin

A previous build attempt (Robolex) got stuck in tooling and infrastructure complexity. The lesson:
the stack itself can slow the team down before product learning even starts.

## Problem

- Juniors are often put on "training-wheel" stacks that differ from production.
- Seniors then have to translate architecture decisions across two systems.
- Founders pay in rework, debugging time, and slower product iteration.

## Proposal

Offer a Convex-first build + mentoring setup where a junior engineer (for example, a college student
hire) learns on the same production stack used by a senior engineer.

## Suggested slogan options

- Give your junior devs the same stack your senior uses.
- Train juniors on the stack that ships.
- One stack for learning and production.

## Offer structure (productized service)

1. Stack reset: standardize on one stack (Convex + TypeScript + React).
2. Project scaffold: start from a working baseline and ship week 1.
3. Guided execution: senior-led architecture + junior implementation.
4. Skills transfer: code review, pairing, and playbooks.
5. Handoff: junior can run day-to-day, senior stays as escalation.

## Why this works

- Fewer moving parts than split backend/tooling setups.
- Real-time data and backend functions in one place (Convex).
- Same local/prod mental model for both junior and senior.
- Faster path from idea to shipped feature.

## Success criteria

- First production feature shipped in 2-3 weeks.
- Junior can deliver scoped features independently by month 2.
- Senior review cycles focus on product decisions, not stack firefighting.

## Outreach draft

I have a concrete suggestion for your team: put your junior engineer on the exact same stack a
senior would choose (Convex + TypeScript + React), and I can help run that setup. It removes the
"junior stack vs production stack" gap and gets you shipping faster while training the junior on
real production patterns.
