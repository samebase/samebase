# builder-workflow SKILL

## When to use
User says shorthand commands like "push", "create pr", "wait", "ship"

## How to execute

### create pr
- Use `gh pr create --draft --fill` 
- Never tell user to click UI buttons
- If branch not pushed, push first

### push  
- Stage and commit if changes exist
- Push to remote
- Create/update PR if appropriate
- Mark draft as ready if requested

### wait
- Use `gh pr checks` or `gh run watch` to monitor
- Report status, don't just say "check the UI"

## Critical rules
- Always use CLI tools (gh, git) over UI instructions
- Execute, don't instruct
- Adapt to context (e.g., if PR exists, update it)
