## Vetted findings NOT planned this run (deferred, with reasons)

These were confirmed real but fell below the planning cut. Re-rank rather than re-audit:

- **OAuth state consumed only after token exchange** — `apps/noter/convex/githubOAuth.ts:184-226`
  (same shape in `convexOAuth.ts`/`cloudflareMcpOAuth.ts`). The audit initially rated this MED-HIGH;
  vetting downgraded it: the final store+delete (`storeGithubOauthConnection`) is a single atomic
  transaction (nested `runMutation` from a mutation shares the parent transaction), and GitHub
  authorization codes are single-use, so duplicate credential writes cannot persist. Residual: a
  double callback can 500 (the catch path deletes an already-deleted state doc, which throws).
  Hardening, S effort: consume (validate+delete) the state in one mutation before the token
  exchange.
- **`connectedMachineHttp` endpoints only helper-tested** — the three httpActions (registration,
  heartbeat, token introspection) have no endpoint-level tests; only
  `machineHeartbeatHasConsistentLiveControlState` is covered. M effort via `convex-test`'s
  `t.fetch`.
- **Unbounded `.collect()` in staging list queries** — `fileStaging.ts:481-542` returns every staged
  doc (with full contents) per subscription update; bounded in practice by staging size, but
  violates the repo's own Convex guidelines. Pagination is a client-visible change; do it when
  staging row counts justify it.
- **Both editors statically imported** — `CodeEditor.tsx:19-20` imports `MonacoEditor` and
  `CodeMirrorFileSurface` at module level, so CodeMirror/prosemark always ship in the entry bundle
  (`@monaco-editor/react` lazy-loads Monaco core itself). M effort (React.lazy + Suspense), MED risk
  on editor focus/mount behavior — the repo treats editor surfaces as high-care.
- **`stagingRebase.ts` merge logic has only 5 tests** — characterization gaps: empty files, missing
  trailing newlines, comma/odd paths, large diffs.
- **`gitOperations(.Actions).ts` untested** — blob dedup/idempotency and repository download logic;
  L effort (needs git/io mocking).
- **Provisioning workflow orphans the GitHub repo on mid-flight failure** —
  `appProvisioningWorkflow.ts:122-147`: `create_github_repo` succeeds, later steps fail → repo
  exists, vault doesn't; no compensation action. Real, but the fix is a design decision
  (compensating delete vs. retry-only UX) — needs maintainer input before planning.
- **`VaultDashboard.tsx` god-file (6,385 lines)** — top churn file, 60 imports, dialogs defined
  inline. The team is already extracting pieces incrementally; a big-bang decomposition plan would
  be HIGH risk for an executor model. Continue the incremental extraction instead.
- **Collab-sync helper duplication** — `awaitTimeout`/`pushUpdates` duplicated between
  `CodeEditor.tsx:27-66` and `MonacoEditor.tsx:23-60` (the file even says "shared logic with
  CodeEditor.tsx"). Only the helpers are extractable (the orchestration differs by design:
  ViewPlugin vs. hooks). S effort, do it next time either file is touched.
- **`workspace-layout-v2-solid` is a dormant lab app** — zero imports, not in CI filters, only
  standard deps. Cognitive-load cost only; whether to archive it is a maintainer call (the repo
  keeps labs deliberately).

## Findings considered and rejected

- **Polar webhook idempotency** (audit: "retries re-apply billing state"): rejected — the handler
  fetches current state from Polar's API and applies absolute values, so retries are naturally
  idempotent; only `billingUpdatedAt` churns. Not worth a dedup table.
- **OAuth duplicate-credential race as originally reported**: rejected — nested `runMutation` from a
  mutation shares the parent transaction; the upsert+state-delete is atomic (see deferred entry
  above for the real, smaller residual).
- **`findSequenceStart` empty-sequence handling** (`stagingRebase.ts:43`): by-design — `null` is the
  correct not-found signal; all three callers handle it.
- **Collaborative version increment atomicity** (`collaborative.ts:180-228`): not real — Convex
  mutations are ACID; an OCC conflict rolls back the whole transaction including the inserts.
- **Hardcoded dev password** (`runtime/localWorktreePasswordAuth.ts`): by-design —
  deployment-profile-gated; production resolves password auth to `off`
  (`deploymentProfile.ts:181-183`).
- **TypeScript 5.9 + tsgo dual setup**: by-design — RFC 030 documents `tsgo` for CLI typechecking
  while stable TS remains vite-plus's peer dependency.
- **`Math.max(...[])` → `-Infinity` in `applyUpdatesToStaging`**: superseded — the whole mutation is
  dead code; plan 004 deletes it.
- **devAuth seeding untested**: real but rejected — internal, dev-only mutations exercised by every
  local bootstrap; the audit also mis-cited the line ranges.
- **RFC 080 stuck in "Proposed"**: by-design-adjacent — objectives largely shipped via
  `workspace-layout-v2`; status reconciliation flagged to the maintainer in plan 005's notes rather
  than planned.
