# Domain name exploration: fractal / self-replicating app

Checked on 2026-05-17.

This pass looked for `.com` names that connect to:

- the original 3x3 logo with the void center, visually close to a Sierpinski
  carpet
- self-similarity / recursion / apps producing apps
- the "same stack as itself" idea

Availability checks used Verisign `.com` RDAP and direct Verisign WHOIS "No
match" checks for the best unregistered candidates. Collision checks used web
search for the exact name and obvious variants. Premium prices are from the
visible marketplace pages linked below. This is not trademark clearance, and
domain availability can change quickly.

Budget note: the original `$1k-$2k` band should be treated as comfortable, not
hard. A truly better name can justify going higher; `ramura.com` at roughly
`$4.5k` is a useful taste benchmark for a short, pronounceable, organic-feeling
name.

## Best recommendation

Register the best hand-reg candidates immediately while deciding:

1. `sierp9.com`
   - Status: unregistered `.com`.
   - Why it works: 6 characters, directly points at Sierpinski + the
     3x3/nine-square mark.
   - Collision notes: exact search results were mostly incidental
     Sierpinski/fractal filenames such as `Sierp3`, not a visible product brand.
   - Risk: "Sierp" needs explaining and may be heard as "SERP".

2. `sierpx.com`
   - Status: unregistered `.com`.
   - Why it works: 6 characters, abstract and sharper than spelling out the
     math. Reads like "Sierp X", a recursive/generative system.
   - Collision notes: no meaningful exact-name product collision found in the
     search pass.
   - Risk: pronunciation is not obvious.

3. `recursr.com`
   - Status: unregistered `.com`.
   - Why it works: 7 characters, directly carries the self-replicating /
     recursive app idea.
   - Collision notes: exact name is used by an R recursion-schemes package,
     [`recursr`](https://druimalban.github.io/).
   - Risk: dropped-vowel spelling is voice-hostile, but still memorable in a
     developer context.

4. `sierpgrid.com`
   - Status: unregistered `.com`.
   - Why it works: explicit visual/logo story, still only 9 characters before
     `.com`.
   - Collision notes: no meaningful exact product collision found; search mostly
     surfaced Sierpinski teaching material.
   - Risk: more literal and less brand-like than `sierp9.com`.

5. `fractagrid.com`
   - Status: unregistered `.com`.
   - Why it works: says fractal + grid without relying on the user knowing
     Sierpinski.
   - Collision notes: no meaningful exact product collision found in search.
   - Risk: 10 characters and a bit constructed.

  Results were mostly the domain listing, source-code variable names, academic
  text, product descriptions where "same" and "base" were accidentally joined,

- Package registries: `samebase` was not found on npm, PyPI, crates.io,
  RubyGems, Packagist, or NuGet.
- Developer handles: `github.com/samebase` returned 404, GitHub API returned
  `Not Found`, and GitLab's public user lookup returned `[]`.
- Social handles: `@samebase` is occupied on Instagram by a low-signal profile
  named "Samebase" with mental-wellness copy, 1 follower, and 0 posts. YouTube
  `@samebase` is also occupied by a channel titled "same base". Bluesky
  `samebase.bsky.social` exists with 0 posts and 8 followers, though buying the
  domain would let us use `samebase.com` as the Bluesky handle. LinkedIn
  `/company/samebase/` returns 404, and X/Twitter's public oEmbed endpoint
  returns 404 for `samebase`, but both should be verified while claiming because
  social availability checks can be brittle when unauthenticated. TikTok needs a
  logged-in/in-app confirmation.
- Judgment: this is cleaner than expected. The main risk is not a visible
  trademark/company collision; it is that two consumer-social handles are
  already taken. For a product whose core shtick is "an app creating apps from
  its own base/template", `samebase.com` is still the best paid candidate in
  this pass. If this becomes the leading brand, buy the `.com`, file the mark,
  and claim reachable handles immediately.

### Independent second-pass recommendation

Checked again on 2026-05-17 after reframing the budget as flexible and the MVP
as "an app creates apps from the same template/stack as itself". I tried to
discount prior preference and compare the strongest names as company assets.

| Name        | Score | Decision               | Why                                                                                                                                                                                    |
| ----------- | ----- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `samebase`  | 8.6   | Best candidate         | Clear MVP fit, easy to say, exact USPTO query returned `0` hits, package/developer handles look open, exact web results are mostly the domain listing and generic phrase uses.         |
| `samecore`  | 6.8   | Usable but not better  | Easy to pronounce, but noisier: occupied GitHub user, occupied Instagram/YouTube handles, "Samecore Solution" on LinkedIn, a cancelled Singapore business, and generic technical uses. |
| `samestack` | 5.2   | Do not buy at `$3,285` | Strong concept fit, but the fresh pass found an active Red Hat/Fedora-oriented SameStack framework/package trail from 2025-2026. It also sounds more infrastructure-jargon than brand. |
| `recursr`   | 5.0   | Keep as fallback only  | You already got the domain, but the dropped vowel is voice-hostile and an R package uses the exact spelling.                                                                           |

Reasoning: if the name has to carry a company, `samebase` is better than
`samecore` even though both pronounce well. `samecore` has a clean sound, but it
is more generic in technical language and visibly more occupied on public
profiles. `samebase` also maps to the product better: users create something
from the same base/template, not necessarily from the same kernel/core.

Financial recommendation: because `$2k` is still a meaningful amount, do not buy
`samebase.com` as a speculative "maybe". If the product direction is stable
enough that this could be the company name, it is a rational purchase at
`$1,995`, subject to a real trademark attorney clearance before public launch.
If an attorney finds no hidden conflict, I would rather pay `$1,995` for
`samebase.com` than `$3,495` for `samecore.com` or `$3,285` for `samestack.com`.

## My ranking

If the brand should lean into the logo/math story:

1. `sierp9.com`
2. `sierpx.com`
3. `sierpgrid.com`

If the brand should be understandable without explaining Sierpinski:

1. `samebase.com`
2. `recursr.com`
3. `fractagrid.com`

If spending real money:

1. `samebase.com` is still the cleanest paid candidate because it is
   pronounceable, on-concept, and surprisingly uncrowded.
2. `samecore.com` is viable, but I would put it behind `samebase.com` because
   the product story is base/template more than "core", and because the open web
   is noisier.
3. Avoid `samestack.com` at `$3,285` unless a deeper clearance pass proves the
   Red Hat/Fedora SameStack framework/package trail is harmless.
4. `corevoid.com` is viable, but I would only buy it if the product identity is
   intentionally more void/logo-led.
5. Avoid `fracta.com` despite the attractive `$1,000` price because the name is
   already crowded in adjacent AI/software territory.
